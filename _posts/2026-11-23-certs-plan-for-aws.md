## 1. 이 글을 쓰게 된 계기

제 목표는 AWS 취업입니다. 지금까지 활동을 정리해 보니, 공모전과 자격증 칸이 비어 있었습니다. 딴 자격증도, 참가한 공모전도 없습니다.
실습은 많이 했지만 그것을 바깥에서 인정받은 결과는 아직 없습니다. 그래서 왜 비어 있는지와 어떻게 채울지를 정리하기로 했습니다.

## 2. 시작하기 전 처음 질문

| 질문 | 지금 내 생각 |
|---|---|
| 실습을 많이 했으면 자격증은 없어도 될까? | 실습이 더 중요하다고 생각했다 |
| 자격증은 무엇을 증명해 줄까? | 잘 모르겠다 |
| 무엇부터 따야 할까? | 보안 자격증이 바로 필요할 것 같다 |
| 공모전은 나와 맞을까? | 개발 공모전만 있는 줄 알았다 |

## 3. 지금까지의 과정과 결과

### 3-1. 결과

- 딴 자격증: 0개
- 참가한 공모전: 0회

### 3-2. 대신 해 온 것

자격증 취득이나 공모전 참가 경험은 없지만, 실제 AWS 계정에서 여러 서비스를 직접 다뤘습니다.

- EKS 클러스터를 만들고 audit 로그, Container Insights를 켰습니다.
- CloudTrail과 VPC Flow Logs로 공격 흔적을 찾고, GuardDuty의 탐지 결과도 확인했습니다.
- S3 Object Lock으로 증거를 지울 수 없게 보관하고, SSM으로 노드에서 로그를 모았습니다.
- 공유 계정에서 IAM 사용자로 작업하고, 쿠버네티스 ServiceAccount 토큰과 권한(RBAC)이 공격에 어떻게 쓰이는지 직접 확인했습니다.

### 3-3. 돌아보니

이렇게 해 보니 제가 아는 것은 프로젝트에 필요했던 부분뿐이었습니다. 예를 들어 EKS와 로그 서비스는 잘 알게 되었지만, 프로젝트에 나오지 않은 서비스나 설계 원칙은 거의 모릅니다.
자격증은 시험 범위가 정해져 있어서, 제가 모르는 부분을 빠짐없이 찾아 주는 지도 역할을 해 줄 수 있다고 생각을 바꿨습니다. 또 처음 보는 사람에게 제 수준을 짧게 보여 줄 수 있는 방법이기도 합니다.

## 4. 부족했던 점

- 프로젝트에 필요한 부분만 깊게 알고, AWS 전체를 넓게 보지 못했습니다.
- 실습 경험을 바깥에서 확인받은 결과가 없습니다.
- 보안과 클라우드 분야 공모전의 기회와 참가 방법을 더 알아봐야 합니다.

## 5. 앞으로 할 것

- AWS 기초 설계 범위를 다루는 Solutions Architect Associate부터 준비하겠습니다. 프로젝트에서 다루지 않은 서비스를 범위 표로 정리하고, 하나씩 직접 만들어 보겠습니다.
- 그다음 AWS Security Specialty를 준비하겠습니다. IAM, 로깅, 사고 대응처럼 이미 실습한 부분이 많아서, 실습 기록을 시험 범위에 맞춰 다시 정리하는 방식으로 공부하겠습니다.
- 쿠버네티스 보안 자격증도 후보로 두고, 포렌식 랩에서 다룬 내용과 겹치는 부분을 확인하겠습니다.
- 보안과 클라우드 분야 공모전을 찾아보고, 지금 하는 qmon 도구나 포렌식 프로젝트를 낼 수 있는 곳이 있으면 참가하겠습니다.
- 공부한 내용은 시험이 끝난 뒤에도 쓸 수 있게 이 카테고리에 정리하겠습니다.
